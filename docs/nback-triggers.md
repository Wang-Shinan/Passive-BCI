# N-back BDF Trigger（v2）

网页 N-back 默认开启向 OmniBCI 写 Trigger。先在 GUI 启用 Web API / Trigger（8766），
选择 BDF 录制并开始采集，收到首帧后再开始网页实验。仅行为实验可以取消勾选。
若还需网页 EEG 副本，需要另行连接网页数据流并开始网页录制。

事件通过 POST /v1/trigger 发送 code、label。GUI 在 BDF annotations 中保存
`TRIGGER code=... label=...`。用 annotations 区分全部事件：相邻事件可能落在同一个
采样位置，单一状态通道的事件码不足以表达该位置的所有事件。

## 事件码

- 100：区块开始；300：完整结束；301：中止。
- 110+N：记忆试次字母出现；120+N：正式非目标出现；130+N：正式目标出现。
- 140+N：记忆字母消失；150+N：非目标消失；160+N：目标消失。
- 201：记忆阶段按键；202：目标命中按键；203：非目标误报按键。
- 400：记忆试次结束；401：命中；402：漏报；403：误报；404：正确拒绝。

N 为 1、2、3。原刺激出现和区块码保持不变；旧版统一按键码 200 不再产生。
漏报和正确拒绝发生在反应窗口截止时，属于结果分类标记，不是实际按键。
中止时若字母仍显示，先记录一次消失，然后记录中止，不生成未完成试次的结果。

## 标签与关联

例：`nback:v2:b=<完整block UUID>:n=2:t=5:e=trial_end:l=R:c=hit:rt=453.2`。
`t` 是包含前 N 个记忆试次的零基索引；区块事件为 `-`。
`l` 为字母；`c` 为刺激条件或结果；`rt` 为毫秒反应时，无反应为 `-`。
按 block UUID 和试次索引关联出现、消失、反应、结果。
GUI 注释标签包含这些字段，不需要仅靠网页文件推断正式试次结果。

网页保留原始事件、trigger_request、trigger_ack / trigger_error；失败不自动重试，
以免重复打标。结束后等待页面的 Trigger 等待数归零，并检查未确认数，再停止 GUI 录制。
软件事件不等同于屏幕真实发光时间。本次修改不改变时钟同步方式。

## 已知限制：EEG 到达停顿时的同点标记

当前 GUI 将 HTTP trigger 绑定到处理请求时的 `latest_sequence`，录制器再将该序号
映射为 BDF 采样位置。如果 EEG 数据暂时未更新，期间分别收到的出现与消失事件
会落到同一个采样点；Annotations 保留两个事件，Status 通道低 16 位会被后一个码覆盖。

2026-09-17 的一次完整区组中发现 6 对此类事件。网页发送间隔约 304–315 ms，
请求往返约 16–80 ms；对应网页 EEG 批次到达间隔约 476–547 ms，后续样本序号连续。
这些记录支持“最新样本未更新导致重复绑定”，不能据此判定设备停止采样，也不能
仅凭现有日志将停顿归因于 BLE、设备缓存或主机处理中的某一环节。

这一限制尚未修复。改用 WebSocket 发送 trigger 本身不能修复序号绑定问题。
ERP 分析需检查标记间隔；不能把 onset=offset 当作真实显示时长，或将这类事件
当作已验证的精确刺激对齐。后续需建立事件时钟与采样时钟映射，或使用设备硬件触发。

## BDF 切段与平均

`scripts/average-nback.py <GUI录制元数据.json> --block <区组UUID>` 按 GUI BDF
出现/消失注释切段，包含出现前 200 ms 基线，分别平均命中与正确拒绝。
先对连续数据做 0.1–30 Hz 滤波，保留原参考；输出逐题数组、条件平均、试次数曲线
和 PNG/PDF。缺失事件、同点出现/消失和越界片段不会进入变长切段。

默认只处理已完成录制和完整区组。`--allow-live-snapshot` 读取正在录制的 BDF
完整数据记录副本，`--include-interrupted` 允许使用中断区组中已完成的题目。
原始录制不被修改。变长切段后半段参与平均的试次数会减少，不能把由此出现的
阶跃直接解释为 ERP。幅值和时长筛选仅用于探索性质量检查。
