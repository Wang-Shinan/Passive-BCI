## 用户流程与页面方案

首轮保留现有 URL、实验名称和入口可达性。下列分类调整是本方案的建议，尚未应用。

### 首页与全局导航

将首页组织成“当前状态 → 常用操作 → 完整实验目录”。顶部展示真实设备状态、数据模式、录制状态和运行中模型摘要；无连接时明确显示未连接，不填演示数值冒充状态。

建议导航分组：

| 分组 | 现有页面 |
| --- | --- |
| 采集调试 | `/acquisition` |
| 实验 | `/nback`、`/rl-graph`、`/tetris`、`/card-cit`、`/jump`、`/draw-guess`、`/dino`、`/schulte` |
| SMR 与眼动 | `/smr-gaze`、`/smr-ud`、`/smr-adapt`、`/tetris-adapt`、`/gaze-smr-tetris`、`/gaze-tetris` |
| 会话库 | `/recordings` |
| 训练与适配 | `/training`、`/online-learn` |

`/stress-remote` 保留独立窗口形态，不套完整导航。模型配置继续提供任务相关的统一面板入口，第一阶段无需增加新的模型中心路由。

完整实验目录采用紧凑列表或适量分组卡片，显示“任务名称、简要目的、支持的数据模式、前置条件”。分类描述来自审核过的目录元数据；“当前可运行”必须根据实时能力判断。最近使用入口只有在确有本地使用记录时才出现。

### 公共外壳与状态条

建议结构为 `AppShell → SideNav + PageHeader + RuntimeStatusBar + 页面内容`。侧栏服务于主试操作页；实验页逐个决定是否使用紧凑外壳。状态条不直接连接设备，不启动模型，也不接管实验时钟。

状态必须分别展示：

- 数据模式：手动、演示、实时 EEG。
- 设备：未连接、连接中、已连接未开流、正在采集、数据过期、错误。
- 模型：待选头与运行中头分别显示；需要时展开任务、revision、通道、采样率。
- 录制：未开始、录制中、保存中、保存成功或失败。显示的数据取自相应所有者，不仅依据按钮点击推断成功。

高频 EEG 数据留在现有缓冲与 Canvas 渲染路径。状态摘要使用独立订阅、稳定快照和有限频率的 UI 更新；不将原始样本放入顶层 React Context。紧急停止始终可达，不能折叠进高级设置。

### 采集页

保留当前波形、频谱、地形图、阻抗功能与专用画布。将界面分为设备连接区、信号观察区、显示设置、录制摘要。高级参数采用逐步展开，但保留重要错误、丢包、延迟和录制异常的可见性。

先抽取设备配置与工具栏等纯视图；后续再抽取对应控制 hook。保留 `acqRuntime` 在模块层的生命周期，路由切换仅解绑 UI 订阅。必须保留“显示滤波副本”和“记录原始样本”的明确区分。

### 实验页

形成“实验准备、执行、结束回看”的视觉层级。设置栏、状态栏和结果栏可复用；试次状态机、按键规则与控制映射仍归各实验所有。

主试控制区与被试刺激区分开。首次迁移只调整控制区。对刺激区的尺寸、背景亮度、字体、位置、动画、全屏行为或响应按键的改动，单独列为实验变更，重新验证后才能使用。状态更新不能导致刺激区域重挂载或重新计时。

`/tetris`、`/gaze-smr-tetris`、`/gaze-tetris` 保留各自协议。前者 gaze 的 down 不触发脑控动作，后两者 down 表示软降；纯 gaze 路径不改成 REVE 头路径。公共组件只共享外观与明确相同的控制行为。

### 会话库与训练

会话库沿用列表和详情结构，统一筛选器、字段排版、状态显示和空状态。保留删除确认与错误反馈。训练页保留“选会话 → 导出 H5 → 训练 → 查看评估 → 设为待选头”的依赖关系。

优先将现有界面整理为明确的步骤区域，不建立阻止用户回看结果的强制向导。让数据量、类别覆盖、会话/试次划分方式和失败原因出现在作出决定的位置。“设为待选线性头”必须继续区别于“应用到运行模型”。

## 视觉规范提案

保留项目现有的深色主调和蓝色操作色。采集工作站作为明确的浅色功能区域保留，分阶段映射到语义 token；被试刺激表面独立于管理界面主题。

| 项目 | 建议 |
| --- | --- |
| 颜色 | 沿用 `#0b1020` 背景、`#141b2d` 面板、`#5b8cff` 主色作为起点；按钮文本组合另行测量对比度 |
| 语义色 | 绿色用于成功/有效连接，橙色用于警告，红色用于错误或停止；文字同步说明，不单靠颜色 |
| 字体 | 管理界面使用现有无衬线体系，并明确中文系统字体 fallback；数值使用等宽数字。字体资产需确认实际存在，刺激字体单独锁定 |
| 字号 | 页标题 24px、分组标题 16–18px、正文 14–16px、辅助文字 12–13px；不改变刺激字号 |
| 间距 | 4/8/12/16/24/32px；以排版分组替代面板套面板 |
| 圆角 | 控件 6px、分组容器 10px、标签 4px；首批新外壳采用新值，旧实验不通过全局选择器同步替换 |
| 宽度 | 主试工作区边距 24px，侧栏约 208px；采集波形使用可用宽度。实际值须经 1280px 和 1440px 页面核验 |
| 动效 | 普通交互保留 100–150ms 颜色反馈；管理 UI 支持 reduced motion。实验刺激动画按协议单独处理 |
| 小屏 | 导航折叠、设置区重排；明确哪些实验需要桌面/全屏条件，不擅自压缩刺激尺寸 |

图标如需引入，统一选择一个库；首轮不为外壳新增动画库、图表库或状态管理库。现有 Recharts 与 Canvas 各自承担原有职责。

## 前端代码组织

渐进增加以下模块，不整体搬迁目录：

```text
src/app/
  AppShell.tsx
  SideNav.tsx
  PageHeader.tsx
  RuntimeStatusBar.tsx
  experimentRegistry.ts
src/lib/ui/
  Button.tsx
  Field.tsx
  StatusBadge.tsx
  EmptyState.tsx
  ErrorState.tsx
  Panel.tsx                  # 在原组件上渐进扩展
src/acquisition/components/ # 设备表单、显示设置、录制摘要
src/acquisition/hooks/      # 视图订阅与设备控制适配
src/experiments/<name>/     # 各实验保留独立 engine、contracts、测试
```

`experimentRegistry` 首轮只维护 ID、现有路径、展示名称、分类、说明和数据能力元信息。它可供导航及会话库显示复用，但不承担试次运行、自动判断录制兼容性或生成模型标签映射。

对于大页面，先提取无副作用组件，再提取已有逻辑的 hook。拆分目标是让页面组装、设备控制、记录生命周期和刺激渲染各有明确所有者；文件行数只作为观察指标，不设置机械的行数门槛。

路由懒加载单独实施：先盘点静态导入所承担的初始化、运行时注册和 CSS 加载；把必要运行时启动保留在稳定入口，再为实验模块引入动态加载、加载状态及失败恢复。不能因拆包导致设备只在打开某页之后才初始化，或换页时断开会话。

Vite 的模型服务、录制、训练及诊断插件暂时保留。本次打包通过只证明前端产物可构建，不能证明静态部署能够提供 `/api/*` 服务；若未来独立部署后端，另立迁移方案。

## 必须保持的实验与数据约定

1. 模型选择与应用分离；录制中不能更换 URL、任务、头、步长或后端。
2. 保留跨标签页模型/录制互斥、操作所有权与取消语义；迟到的启动响应不能覆盖停止操作。
3. 紧急停止仍可在加载或录制期间执行，停止后不能自动重连。
4. 模型预测必须通过任务、类别顺序、revision、freshness 检查；gaze 还需被试、通道顺序和采样率匹配。
5. `brain_model_binding`、记录事件、标签含义、原始采样与时间基准保持稳定；最终 flush 的完成语义必须验证。
6. N-back onset、反应时、停止保存、重试逻辑保持；被试刺激区域不挂载通用页面转场动画。
7. 训练保留按会话或原始试次分组的隔离与类别覆盖约束，不能为了展示统一而重新解释数据划分。

依据：当前 `MERGE_NOTES.md` 及已阅读的 `modelServiceApi.ts`、`modelOperation.ts`、`useModelConfiguration.ts`、`brainControlTask.ts`、`GazeTetris.tsx`、`training/index.tsx`。这些约定仍需行为测试覆盖，不把文档陈述当作硬件验证。
